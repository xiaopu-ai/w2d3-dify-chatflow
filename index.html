🥚 你发现了彩蛋：多 Agent 还能这么玩

下面两个只给思路，不给教程。自己搭、自己测，做出来截图发群里。

C · 并行「复习卡」模式

分模式 → 新增分类「全面复习」
   ├→ 讲解 Agent
   ├→ 出题 LLM        （三路同时跑）
   └→ 面试官 Agent
          ↓ 三路汇合
   LLM「复习卡汇总」→ 直接回复
  • 给分类器加一类「全面复习」，接住「帮我全面复习 RAG」这种请求
  • 从这个出口同时拉出三条线，三路一起跑
  • 三条线汇到一个 LLM，合成一张复习卡：讲解 + 5 道题 + 3 道面试题
提示：并行分支的结果不能用变量聚合器合并（它只管「每次只走一条」的互斥分支），要用 LLM 或模板转换来合并。
自己测：三路同时跑，总耗时是三路加起来，还是等最慢的那一路？三路里哪一路其实不需要 Agent？

D · 主管式一句话里要两件事

用户：「讲讲 RAG，再出 3 道面试题」
  → 主管 Agent
      工具：答疑工具 / 面试题工具 / 出题工具
      ├─ 先调「答疑」
      └─ 再调「面试题」
  → 主管把两份结果合成一个回答
  • 把「答疑」「出面试题」各做成一个 Workflow（里面放 LLM 或 Agent），发布为工具——和今天的「查课程笔记」一个做法
  • 新建一个 Chatflow，只放一个「主管 Agent」，工具列表挂上这几个工具
  • 让主管自己决定：拆成几件事、先调谁后调谁
提示：Dify 的 Agent 节点不能直接调用另一个 Agent，所以子 Agent 要先包成 Workflow 工具。
自己测：同一句混合请求，路由版、多 Agent 版、主管版各答得怎么样？主管拆错、漏调了怎么办？它比路由版贵多少、慢多少？
没有标准答案，也没有教程。搭不出来也正常，搭出来就是面试时最好的故事。
